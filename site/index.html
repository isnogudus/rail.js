Workflows as explicit graphs.

A small JavaScript library that turns nested control flow into named nodes, named outputs, and visible wires. Compile-time validated, async end to end, Mermaid-friendly — and not a single runtime dependency.

01 / Problem

Nested try/catch hides the path through your logic.

“Send a message” sounds simple. In practice it’s validation, encryption, network errors, retries, abortable I/O, cleanup. In imperative JavaScript that becomes a nest of try/catch blocks where, three refactors in, nobody can tell which path leads where.

Before — imperative
async function sendMessage(ctx) {
  if (!ctx.roomId) {
    return { ok: false, error: 'INVALID' };
  }
  let encrypted;
  try {
    encrypted = await encrypt(ctx);
  } catch (e) {
    if (e.name === 'NoKeysError')
      return { ok: false, error: 'NO_KEYS' };
    throw e;
  }
  try {
    await fetch(ctx.url, { body: encrypted });
    return { ok: true };
  } catch (e) {
    if (e.name === 'NetworkError')
      return { ok: false, error: 'NET_5xx' };
    throw e;
  }
}
After — the graph is the control flow
const sendMessage = activity((a) => {
  const start = a.entry('in');
  const { success, failure } = a.standardExits();

  const validate = a.addNode('validate',
    node(validateFn, { outputs: ['ok', 'invalid'] }));
  const encrypt = a.addNode('encrypt',
    node(encryptFn, { outputs: ['ok', 'noKeys'] }));
  const send = a.addNode('send', catching(
    node(sendFn, { outputs: ['ok'] }),
    { NetworkError: 'net5xx' }
  ));

  a.wire(start,                  validate);
  a.wire(validate.out('ok'),     encrypt);
  a.wire(validate.out('invalid'), failure);
  a.wire(encrypt.out('ok'),      send);
  a.wire(encrypt.out('noKeys'),  failure);
  a.wire(send.out('ok'),         success);
  a.wire(send.out('net5xx'),     failure);
});
02 / Concept

Three building blocks. One uniform interface.

Every Rail-Node — whether a single step, a composed activity, or a parallel fan-out — exposes the same contract: compile(), compiled(), invoke(name, ctx, runState). Composing workflows is therefore just adding nodes.

railKind: 'step'

Step-Node

Wraps a user function with declared input and output ports. A failed step doesn’t throw — it returns a named output. 

node(fn, { outputs: ['ok', 'failed'] })
railKind: 'activity'

Activity

A graph of named sub-nodes connected by wires. Compiles in three phases. Composes recursively: an activity can be added as a sub-node of another activity. 

activity((a) => { /* ... */ })
railKind: 'parallel'

Parallel-Node

Runs branches concurrently via Promise.allSettled. Each branch gets its own fork of the run-state and a combined abort signal. Returns a typed parallel-results ctx. 

parallel({ profile, keys, audit })

A flow holds one node and runs it.

flow(name, node) is the only stateful boundary — and it’s actually stateless. Each run(ctx, opts) allocates a fresh run-state in its own closure, so the same flow object can be invoked concurrently any number of times, with its own logger, tracer, and signals per call.

flow.run(ctx, opts)
→ { ctx, trace, terminus }
03 / Compile

Three phases catch the bugs before the first run.

Wire-direction, port-typo, and cross-builder mistakes are caught synchronously at the call site. activity.compile() then runs three phases — declaration, completeness, topology — collecting every issue in a phase before short-circuiting.

A Declaration NO_ENTRY · DUPLICATE_NODE · NOT_A_NODE
B Completeness UNWIRED_OUTPUT · ENTRY_NOT_WIRED · EXIT_NOT_WIRED
C Topology UNREACHABLE_NODE · CYCLE · UNREACHABLE_EXIT

Idempotent. compile() on an already-compiled node returns immediately, so sharing a node across activities compiles it exactly once.

Recursive. Compiling an outer activity recursively compiles every sub-node and every parallel branch, with path hints in the error.

Convergent inputs are intentional. Multiple wires ending at the same node-input are allowed — “no matter which path led here, continue from this node.”

No exception magic. The library has no throws mechanism. Steps that interact with throwing code do try/catch themselves, or wrap a Step-Node with catching(...).

05 / Features

      

        
Small surface, sharp edges where they matter.

      

    


    

      

        

          
        

        
Compile-time validation

        
Structural bugs surface at compile(), not in the third
          production incident. Phase reports collect every issue before they
          bubble up.

      

      

        

          
        

        
Live tracer

        
Structured events for every lifecycle scope — run, step, activity,
          branch — each with start, end, throw. Perfect for a live UI of the
          run.

      

      

        

          
        

        
Parallel without magic

        
parallel({ a, b }) runs branches concurrently with
          Promise.allSettled and an internal abort linkage on the
          combined cancellation signal.

      

      

        

          
        

        
Mermaid render

        
flow.toMermaid() produces a flowchart string ready to
          embed in markdown, READMEs, or live renderers like this page.

      

      

        

          
        

        
Cancellation

        
Cooperative signal exposed to steps as runInfo.signal,
          plus a hard killSignal the runner checks between nodes.
          Standard AbortSignal on both.

      

      

        

          
        

        
Plain ESM

        
No bundler, no TypeScript pipeline, no runtime dependencies. Plain
          JS with JSDoc, runs in modern Node and modern browsers alike.
